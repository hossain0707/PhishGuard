# Publishing and mobile feasibility

## Common release requirements

Approved browser-store listing URLs may be set using optional PHISHGUARD_STORE_CHROME_URL, PHISHGUARD_STORE_EDGE_URL and PHISHGUARD_STORE_FIREFOX_URL public build variables. The generated website links to a store only when an actual verified official host URL is configured. Otherwise it displays clearly labelled development ZIP downloads. Never invent an approval or store link.

Use versioned packages generated by `npm run build`. Confirm package manifests, matching downloads, permission justifications, privacy policy, operator support contact, screenshots and icons. A provisional PhishGuard shield mark is provided as SVG and 16/32/48/128-pixel icons. Add your approved final project/GMI assets; no institutional logo was invented. A store listing must not claim guaranteed phishing prevention, universal mobile support or server-synchronised history.

The privacy page is a draft product disclosure. Add the real operator identity and support/deletion contact before publication. Account email/name and browser registration metadata are transmitted to Supabase; Firefox's personal-information collection declaration reflects this. No browsing-history upload is claimed.

Firefox declares browser/version metadata as optional technical-data transmission. Browser registration runs only when that optional consent is granted; users can request it with Register this browser in Profile. Authentication and local monitoring continue without optional registration.

`storage` stores local assessments and session credentials. `tabs` permits URL inspection, current-tab results and risk redirects. HTTP/HTTPS site access is needed to scan those pages. The previously unused `activeTab` and `webNavigation` permissions were removed. Extension account/report pages are no longer exposed as web-accessible resources.

## Chrome

Register a Chrome Web Store developer account, complete the account requirements, upload the Chrome/Edge ZIP, supply listing assets, explain the extension's single purpose and permissions, disclose data handling, provide the public privacy URL, and submit for review. Supply reviewer instructions/access for login-required features. Fees and account verification are handled by the store account owner.

Official guide: https://developer.chrome.com/docs/webstore/publish

## Edge

Register in Microsoft Partner Center for the Edge program, upload the tested package, fill in listing and privacy/permission fields, provide reviewer notes, and submit for certification. Sharing Chromium code does not replace independent Edge testing or certification.

Official guide: https://learn.microsoft.com/en-us/microsoft-edge/extensions/publish/publish-extension

## Firefox

Submit through Mozilla's Add-on Developer Hub. Run `npm run lint:extension` (Mozilla addons-linter), disclose the relevant collected data, and supply original source plus reproducible build instructions for the bundled dependencies. Select listed distribution or signed unlisted distribution as appropriate. The supplied ZIP is a development package, not an approved signed XPI. Desktop Firefox uses background scripts rather than a Chrome service worker.

Official guides: https://extensionworkshop.com/documentation/publish/submitting-an-add-on/ and https://developer.mozilla.org/en-US/docs/Mozilla/Add-ons/WebExtensions/manifest.json/background

## Mobile

Firefox Android remains a future feasibility target; the desktop marketplace manifest does not declare Android support. Validate on an actual device and check supported APIs and PDF/download behaviour before enabling Android distribution. Mobile layout screenshots alone are not compatibility evidence.

Standard mobile Chrome does not provide the desktop extension install workflow. Safari iPhone/iPad requires separate Apple packaging/distribution and platform testing. A mobile URL-checking website could be future work, but would not inspect arbitrary browser pages like an installed extension. No Edge mobile support claim is made without checking that platform's supported extension distribution and APIs.

Official references: https://extensionworkshop.com/documentation/develop/developing-extensions-for-firefox-for-android/ ; https://support.google.com/chrome/answer/2664769?hl=en ; https://developer.apple.com/documentation/safariservices/safari-web-extensions
